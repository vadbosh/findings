# findings

**ИИ-ассистент замечает ошибки, пока занят другой задачей. findings заставляет
его сказать о них — один раз, в конце ответа — и хранит каждую находку, пока вы
не решите, что с ней делать.**

Ошибка в файле, который ассистент только прочитал. Конфиг, который делает не то,
что обещает. Прод-алерт, который горит неделю. Ассистент упоминает такое мимоходом
— «отдельная задача, если нужна» — посреди длинного ответа, и к следующему экрану
находка пропадает. На длинной задаче половину найденного вы так и не увидите.

findings решает это тремя частями: правило говорит ассистенту, куда писать
находку; хук проверяет, что правило соблюдено; журнал хранит каждую находку, пока
вы не ответите fix, park или skip.

Claude Code · Codex · Opencode. Проверено на Linux; на macOS должно работать, но не проверялось.

## Как это выглядит

Ответ заканчивается секцией — только с находками, новыми в этом ответе. В русской
сессии секция русская:

```markdown
Готово: миграция проходит, тесты зелёные.

## Найдено попутно

1. [связано] `/srv/app/db/migrate.py:88` — откат не удаляет созданный индекс — прочитал down(). Исправить?
2. [не связано] `/srv/infra/alerts/coredns.yaml` — 8 правил не деплоятся: каталога нет в alert_rule_dirs. Исправить?
3. [срочно][не связано] прод: `KubernetesHPAScalingAbility` горит 7 дней — не проверено. Исправить?
```

Следующий ответ их не повторяет. Они в журнале:

```
$ findings list --all
findings: /srv/app
  F12 [related] `/srv/app/db/migrate.py:88` — откат не удаляет созданный индекс …  — 2026-10-01

findings: /srv/infra
  F14 [urgent][unrelated] прод: `KubernetesHPAScalingAbility` горит 7 дней — не проверено.  — 2026-10-01
  F13 [unrelated] `/srv/infra/alerts/coredns.yaml` — 8 правил не деплоятся …  — 2026-10-01
```

Отвечаете одной строкой — в чате или командой:

```
fix 12 · park 13 · skip 14
/findings park 13-14
```

## Когда находки показываются

| Момент | Что в ответе |
|---|---|
| найдена ошибка | секция с этой находкой — один раз |
| следующие ответы | о ней ничего |
| `[срочно]` — утечка секрета, потеря данных, авария на проде | повторяется в каждом ответе, пока вы не решите |
| задача закрыта (коммит, push, «готово»), перед заметками или передачей дел | сводка: всё открытое и отложенное по проекту |
| вы попросили — `/findings`, «покажи находки» | сводка, рекомендация по каждому пункту и готовая строка ответа |

`park` убирает находку из чата, но оставляет в журнале. `skip` отклоняет её.
`fix` делает её задачей; когда исправление проверено, находка получает статус
`done`. Если находка со статусом `done` появляется снова, она записывается заново:
это регрессия.

## Где хранятся находки

В одном файле на вашей машине: `~/.local/state/findings/ledger.jsonl`. В
репозитории ничего не пишется. У каждой находки в этом файле есть метка
`project`, и по ней фильтрует `/findings`:

```json
{"op": "add", "id": 13, "project": "/srv/infra", "cwd": "/srv/app", "where": "/srv/infra/alerts/coredns.yaml", "tags": ["unrelated"], "text": "…"}
```

Метка — это git-репозиторий, на который указывает путь находки. Ошибка в
`/srv/infra/…`, найденная во время работы в `/srv/app`, получает метку
`/srv/infra`: `/findings` покажет её, когда вы в следующий раз будете работать в
`/srv/infra`, а в `/srv/app` — нет. Находка без пути или с путём вне
git-репозитория получает метку репозитория, в каталоге которого идёт сессия;
если и этот каталог вне git, меткой становится он сам. `/findings all` показывает
весь файл, сгруппированный по меткам.

## Установка

```bash
git clone https://github.com/vadbosh/findings
cd findings
./install.sh --dry-run    # что будет записано
./install.sh
```

Потом перезапустите ассистента: хуки, правила и плагины читаются при старте.

Установщик ставит findings во все найденные ассистенты (`~/.claude`, `~/.codex`,
`~/.config/opencode`). `--ide claude` ограничивает установку одним, `--no-rule`
пропускает файл правила. Повторный запуск ничего не меняет. Файл, который
пришлось бы перезаписать другим содержимым, сначала копируется в
`~/.local/state/findings/backups/`.

Нужен python 3.8+, а чтобы раскладывать находки по репозиториям — git. Пакеты не
нужны.

## Использование

```bash
/findings                 # open and parked, this project (Claude Code, Opencode)
/findings all             # every project
/findings park 4-9        # also: skip, done, open — ids like 3, F3, 4-9, 3,5
/findings fix 3,5         # take them on as the task

findings list [--all] [--status open,park,skip,done|any] [-p PATH]
findings count [-p PATH]  # one line, for hooks and prompts
findings set park 4-9     # or simply: findings park 4-9

# -p PATH: the project of PATH instead of the current directory
```

В Codex нет пользовательских слеш-команд: попросите «покажи findings» или
запустите `findings list`.

## Как это подключено

| | Claude Code | Codex | Opencode |
|---|---|---|---|
| правило — куда писать находку, когда показывать сводку | `~/.claude/rules/` | `~/.codex/memories/` + строка `@` в `AGENTS.md` | `instructions/` + `opencode.json` |
| записать секцию ответа в журнал | Stop-хук | Stop-хук | плагин, на `session.idle` |
| поймать находку, спрятанную в тексте ответа | Stop-хук | Stop-хук | — |
| сообщить модели, что открыто и что срочно | UserPromptSubmit-хук | UserPromptSubmit-хук | плагин, системный промпт |
| `/findings` | ✓ | — | ✓ |

**Как ловится спрятанная находка.** `found-defects-guard` читает готовый ответ.
Если в тексте — вне кода, кавычек и раздела предложений — стоит фраза, которая
откладывает находку («separate task», «also noticed», «out of scope», «отдельная
задача», «попутно нашёл»), ход продолжается один раз, и модель дописывает только
секцию, не повторяя весь ответ. На 1157 реальных ответах хук сработал 26 раз
(2,2%), почти всегда именно на том, что должен ловить. Ложное срабатывание
обходится в одну короткую строку: `(found-defects-guard: false positive)`.
Opencode не умеет блокировать конец хода, поэтому там остаётся только правило.

**Как модель узнаёт о находках.** `findings-hook` добавляет перед каждым запросом
одну строку: сколько находок по проекту открыто, сколько срочных, сколько
отложено, — и текст каждой срочной. Если открытых находок нет, хук молчит
(отложенные не в счёт), и проект без открытых находок ничего не платит.

## Файлы

```
bin/findings              the ledger CLI
bin/findings-hook         UserPromptSubmit hook
bin/found-defects-guard   Stop hook
plugins/opencode/findings.ts
rules/found-defects-last.md
commands/findings.md
lib/wire.py               edits settings.json, hooks.json, opencode.json, AGENTS.md
```

Журнал — один JSONL-файл, в который только дописывают:
`~/.local/state/findings/ledger.jsonl` (`$FINDINGS_DIR` или `$XDG_STATE_HOME`
переносят его). Номера сквозные: F7 — одна и та же находка в любом проекте.
Одновременные сессии пишут по очереди, через `flock`.

Переключатели одинаково работают во всех трёх ассистентах:
`FOUND_DEFECTS_GUARD=off` выключает поиск спрятанных находок, но секция
по-прежнему записывается; `FINDINGS_RECORD=off` выключает запись в журнал.

## Тесты

```bash
bash tests/test_findings.sh            # the ledger: parsing, routing, dedupe, statuses
bash tests/test_found_defects_guard.sh # the guard's decisions
bash tests/test_install.sh             # install, re-install, uninstall, in a temporary HOME
```

Ни один не трогает настоящую конфигурацию и настоящий журнал.

## Удаление

```bash
./uninstall.sh --dry-run
./uninstall.sh
```

Удаляет хуки, плагин, правило, команду и CLI. Журнал остаётся: это ваши данные.
